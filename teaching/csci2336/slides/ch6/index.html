Hashing: Basic Plan

Save items in a key-indexed table, where the index is a function of the key.

Hash function. Method for computing an array index from a key.

A table of 6 slots, and an index that is a function of the key.

Ideal Hashing

With a hash function and no collisions, neither dictionary operation searches:

public void add(K key, V value)
{  hashTable[hash(key)] = value;  }

public V getValue(K key)
{  return hashTable[hash(key)];  }

Chapter 5 searched for the key before storing it, and no implementation did that in less than \(O(n)\). Each line here is a constant number of operations.

Typical Hashing

Step 1. Convert the search key to an integer, called the hash code.

Step 2. Compress the hash code into the range of table indices.

A table of 101 slots, and a phone number for a key.

Issues

  • Computing the hash function.
  • Equality test. Method for checking whether two keys are equal.
  • Collision resolution. Algorithm and data structure to handle two keys that hash to the same array index.

The first two are this part of the chapter. The third is the other three parts.

Classic Space-Time Tradeoff

  • No space limitation. Trivial hash function, with the key as index.
  • No time limitation. Trivial collision resolution, with sequential search.
  • Space and time limitations. Hashing (the real world).

A nine-digit ID as its own index needs a billion slots to hold a class of 25. One slot searched from the front is Chapter 5’s unsorted array at \(O(n)\).

Computing the Hash Function Must Know

Idealistic goal. Scramble the keys uniformly to produce a table index.

  • Efficiently computable.
  • Each table index equally likely for each key.
  • The same index every time for a given key.

The third is what makes a later search find the entry: getValue looks in one slot, and it has to be the slot add computed.

A thoroughly researched problem, still problematic in practical applications.

Ex 1. Phone Numbers

  • Bad. First three digits.
  • Better. Last three digits.
4 phone numbers in one exchange, and a table of 13 slots.

Ex 2. Social Security Numbers

  • Bad. First three digits.
  • Better. Last three digits.

Until 2011 the first three digits were the area number, assigned in chronological order within a geographic region: 573 was issued in California, 574 in Alaska.

Practical challenge. Need a different approach for each key type.

Java’s Hash Code Conventions

All Java classes inherit a method hashCode(), which returns a 32-bit int.

Requirement. If x.equals(y), then x.hashCode() == y.hashCode().

Highly desirable. If !x.equals(y), then x.hashCode() != y.hashCode().

Break the requirement and a search for a key that is in the table computes a different index than the add did, and reports that the key is absent.

Four Kinds of Implementation

  • Default implementation. Memory address of x.
  • Legal (but poor) implementation. Always return 17.
  • Customized implementations. Integer, Double, String, File, URL, Date, …
  • User-defined types. Users are on their own.

The default breaks the requirement for two equal strings, which is why String replaces it. return 17; keeps the requirement and gives every key one index.

Integers, Booleans and Doubles

public int hashCode()                 // Integer
{  return value;  }

public int hashCode()                 // Boolean
{
   if (value) return 1231;
   else       return 1237;
}

public int hashCode()                 // Double
{
   long bits = doubleToLongBits(value);     // IEEE 64-bit representation,
   return (int) (bits ^ (bits >>> 32));     // high 32 bits xor low 32 bits
}

An int key is its own hash code, and a byte, short or char casts to one. For those keys step 1 does nothing, and the whole hash function is the compression.

Strings Must Know

public int hashCode()                 // Java library implementation
{
   int hash = 0;
   for (int i = 0; i < length(); i++)
      hash = s[i] + (31 * hash);      // ith character of s
   return hash;
}
  • Horner’s method to hash a string of length \(L\): \(L\) multiplies and adds.
  • Equivalent to \(h = s_0 \cdot 31^{\,L-1} + \cdots + s_{L-2} \cdot 31 + s_{L-1}\).

Horner’s Method

Ex. String s = "call"; int code = s.hashCode();

Each character of "call" counts as its Unicode value, and the running value is multiplied by 31 at every one of them.

The nesting is Horner’s method, and it is the polynomial \[3{,}045{,}982 = 99 \cdot 31^3 + 97 \cdot 31^2 + 108 \cdot 31 + 108.\]

Question

'c' is 99, 'a' is 97 and 't' is 116.

What is "cat".hashCode()?

  • A 312
  • B 3,282
  • C 98,262
  • D 114,582

\(99 \cdot 961 + 97 \cdot 31 + 116 = 98{,}262\). 312 adds the three values and ignores position, 3,282 is \(3166 + 116\), which drops the multiply at the last character, and 114,582 is "tac".

Performance Optimization

  • Cache the hash value in an instance variable.
  • Return the cached value.
public int hashCode()
{
   int h = hash;                      // return cached value
   if (h != 0) return h;
   for (int i = 0; i < length(); i++)
      h = s[i] + (31 * h);
   hash = h;                          // store cache of hash code
   return h;
}

User-Defined Types

public final class Transaction implements Comparable<Transaction>
{
   private final String who;
   private final Date   when;
   private final double amount;
   ...
   public int hashCode()
   {
      int hash = 17;                                   // nonzero constant
      hash = 31*hash + who.hashCode();                 // reference type
      hash = 31*hash + when.hashCode();
      hash = 31*hash + ((Double) amount).hashCode();   // primitive: wrapper
      return hash;                                     // 31: a small prime
   }
}

Hash Code Design Must Know

A standard recipe for user-defined types.

  • Combine each significant field using the \(31x + y\) rule.
  • If the field is a primitive type, use the wrapper type’s hashCode().
  • If the field is null, return 0.
  • If the field is a reference type, use hashCode(), which applies the rule recursively.
  • If the field is an array, apply the rule to each entry, or use Arrays.deepHashCode().

In Practice, In Theory

In practice. The recipe works reasonably well, and is used in the Java libraries.

In theory. Keys are bitstrings, and “universal” hash functions exist.

Basic rule. Need to use the whole key to compute the hash code.

A function that reads the first field only gives one index to everyone named Maria.

Modular Hashing

Hash code. An int between \(-2^{31}\) and \(2^{31} - 1\).

Hash function. An int between 0 and \(M - 1\), for use as an array index, where \(M\) is the table size and is typically a prime.

Step 2 is the only place the table size appears. Change \(M\) and every index changes, while no hash code does.

Why the Table Size Is Prime

Compression with % keeps a remainder, so a size sharing a factor with the keys leaves slots unreachable. Eight keys, all multiples of 4:

\(k\) 4 8 12 16 20 24 28 32
\(k \bmod 12\) 4 8 0 4 8 0 4 8
\(k \bmod 13\) 4 8 12 3 7 11 2 6

A size of 12 holds the eight in three slots, because \(\gcd(4, 12) = 4\); an even size does it to every even key. A prime shares no factor, so 13 gives each key its own slot. This chapter’s tables hold 13 and 17.

Three Versions of hash()

private int hash(Key key)
{  return key.hashCode() % M;  }                   // bug

private int hash(Key key)
{  return Math.abs(key.hashCode()) % M;  }         // 1-in-a-billion bug

private int hash(Key key)
{  return (key.hashCode() & 0x7fffffff) % M;  }    // correct

% keeps the sign of its left operand, so the first can return a negative index. Math.abs(-2147483648) is -2147483648, because \(2^{31}\) is not an int, and "polygenelubricants" has exactly that hash code. The third clears the sign bit.

Compressing a Hash Code Must Know

The textbook tests the sign instead of clearing the bit, and writes the table size as hashTable.length:

private int getHashIndex(K key)
{
   int hashIndex = key.hashCode() % hashTable.length;
   if (hashIndex < 0)
      hashIndex = hashIndex + hashTable.length;

   return hashIndex;
}

Adding the table length to a negative remainder brings it into range without changing which slot it names. "Rivera" has hash code \(-1{,}846{,}791{,}179\), so % gives \(-12\), and the if makes it 1.

Question

A key’s hashCode() returns \(-45\), and the table has 13 slots.

Which index does getHashIndex return?

  • A −6
  • B 7
  • C 6
  • D −3

-45 % 13 is -6, and -6 + 13 is 7. −6 is the answer without the if, 6 is 45 % 13, the remainder of the code made positive first, and −3 is -45 / 13.

Uniform Hashing Assumption

Uniform hashing assumption. Each key is equally likely to hash to an integer between 0 and \(M - 1\).

Bins and balls. Throw balls uniformly at random into \(M\) bins.

16 bins, and balls thrown into them uniformly at random.

Bins and Balls

Birthday problem. Expect two balls in the same bin after \(\sim \sqrt{\pi M / 2}\) tosses.

Coupon collector. Expect every bin has \(\geq 1\) ball after \(\sim M \ln M\) tosses.

Load balancing. After \(M\) tosses, expect the most loaded bin has \(\Theta(\log M / \log \log M)\) balls.

For the 16 bins in the figure that is 5 tosses, 44 tosses, and about 3 balls. The run shared a bin on toss 5, filled the last empty bin on toss 43, and held 3 in its most loaded bin at toss 16.

Question

Twenty-five keys go into a hash table of 365 slots, and the hash function satisfies the uniform hashing assumption.

What is the chance that some two of the 25 collide?

  • A 0.3%
  • B 7%
  • C 57%
  • D 100%

The 25 miss each other only if each one lands in a bin the others left alone: \(\frac{364}{365} \cdot \frac{363}{365} \cdots \frac{341}{365} = 0.43\). The birthday problem predicts the first collision at \(\sqrt{\pi \cdot 365 / 2} = 24\) tosses, which is where 25 keys are.

Hash Value Frequencies

Java’s String data uniformly distribute the keys of A Tale of Two Cities: every one of the 97 slots takes between 90 and 135 of the 10,615 distinct words, against an even share of 109.
