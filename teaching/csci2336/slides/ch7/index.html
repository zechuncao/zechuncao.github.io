Part 1

Trees

trees · traversals · search trees · heaps

Trees

A tree is a set of nodes joined by edges, with one node named the root, and exactly one path from the root to every other node.

  • A file system: a folder holds files and other folders.
  • The chain of command in an organization.
  • An arithmetic expression, with the operators above their operands.

Trees are drawn upside down, with the root at the top.

Binary Trees

A binary tree is a tree in which every node has at most two children, and each child is either the left child or the right child.

The side matters. A root with one child on the left and a root with one child on the right are two different binary trees, even though both hold two nodes.

Every node in a binary tree is itself the root of a binary tree, which is why almost every method in this chapter is recursive.

The Words for a Tree

A binary tree. Every node has at most two children, and each child is either the left child or the right child.

Levels and Height Must Know

The same tree. Three measures describe it, and all three count edges.

Counting Edges

  • The level of the root is 0.
  • The height of a tree is the largest level in it, so a one-node tree has height 0.
  • The height of an empty tree is \(-1\).

Both counts are edges. The path to H on the last slide holds four nodes and has length 3, and the tree it belongs to has height 3.

Some books count nodes instead and call that same tree height 4. Every answer in this course counts edges.

Question

What is the height of this tree?

  • A 3
  • B 4
  • C 5
  • D 6

The longest path is K, L, N, P, and it has 3 edges. 4 counts the nodes on that path, 5 counts every edge in the tree, and 6 counts every node.

Full and Complete Must Know

Full and complete are two definitions of a binary tree's shape. One is about the children of each node, the other about how the levels fill.

The Two Definitions

  • A binary tree is full when every node has 0 or 2 children. The rule is about each node on its own.
  • A binary tree is complete when every level is filled except possibly the last, and the last fills from the left. The rule is about the levels.

Neither implies the other, and a tree can be both. A tree that is complete and full, with every level filled, is called perfect.

Question

Which description fits this tree?

  • A full and complete
  • B full, not complete
  • C complete, not full
  • D neither

Q has one child, so the tree is not full. Level 2 has a gap on the left with nodes to the right of it, so it is not complete either.

How Many Nodes Fit

A tree of height 3 that is as crowded as a binary tree can be. Level 0 holds the root alone.

Height and Node Count Must Know

A binary tree of height \(h\) holds

\[\text{at most } 2^{h+1} - 1 \text{ nodes}, \qquad \text{at least } h + 1.\]

Turn it around for \(n\) nodes:

  • the smallest possible height is \(\lceil \log_2 (n+1) \rceil - 1\), reached by a tree whose levels are full;
  • the largest is \(n - 1\), reached by a tree in which every node has one child.

A search walks one path, so it costs the height.

Question

What is the smallest possible height of a binary tree with 20 nodes?

  • A 3
  • B 4
  • C 5
  • D 19

Height 3 holds at most \(2^4 - 1 = 15\) nodes, and height 4 holds up to 31. 5 counts the levels rather than the edges, and 19 is the tallest tree of 20 nodes, not the shortest.

Implementing a Binary Tree

Each node is an object holding its data and a reference to each child.

class BinaryNode<T>
{
   private T data;
   private BinaryNode<T> left;
   private BinaryNode<T> right;

   public T getData()                   { return data; }
   public BinaryNode<T> getLeftChild()  { return left; }
   public BinaryNode<T> getRightChild() { return right; }
   public void setLeftChild(BinaryNode<T> child)  { left = child; }
   public void setRightChild(BinaryNode<T> child) { right = child; }
}

A null child is a missing child, exactly as a null next ended a chain in Chapter 3.

Two Recursive Methods Must Know

private int getHeight(BinaryNode<T> node)
{
   if (node == null)
      return -1;
   return 1 + Math.max(getHeight(node.getLeftChild()),
                       getHeight(node.getRightChild()));
}

private int getNumberOfNodes(BinaryNode<T> node)
{
   if (node == null)
      return 0;
   return 1 + getNumberOfNodes(node.getLeftChild())
            + getNumberOfNodes(node.getRightChild());
}

Returning \(-1\) for null is what makes a leaf’s height \(1 + \max(-1, -1) = 0\).

Part 2

Traversals

trees · traversals · search trees · heaps

Visiting Every Node

A traversal visits every node of a tree exactly once. Two families:

  • Depth first goes as far down one subtree as it can before backing up.
  • Breadth first finishes a whole level before starting the next one.

Write V for visiting a node, L for traversing its left subtree and R for traversing its right subtree. The depth-first traversals are the three orders of those three jobs that keep L before R:

  • VLR is preorder, LVR is inorder, LRV is postorder.

Preorder

Depth first, VLR: at every node, visit it, then traverse its left subtree, then its right subtree.

Inorder

Depth first, LVR: traverse the left subtree, then visit the node, then traverse the right subtree.

Postorder

Depth first, LRV: traverse both subtrees, and visit the node only after both are finished.

When the Node Is Visited Must Know

The three traversals do the same three jobs at every node and differ only in when the node itself is visited.

first second third
preorder visit node left subtree right subtree
inorder left subtree visit node right subtree
postorder left subtree right subtree visit node

On the tree above: preorder 15 10 5 11 12 30 20 40, inorder 5 10 11 12 15 20 30 40, postorder 5 12 11 10 20 40 30 15.

Traversal in Code

private void preorderTraverse(BinaryNode<T> node)
{
   if (node != null)
   {
      System.out.println(node.getData());       // V
      preorderTraverse(node.getLeftChild());    // L
      preorderTraverse(node.getRightChild());   // R
   }
}

Inorder and postorder are the same method with the println moved: between the two calls, or after both of them. Nothing else changes.

Question

Which traversal of this tree gives V T W S U X?

  • A preorder
  • B inorder
  • C postorder
  • D level order

S sits in the middle with its left subtree before it and its right subtree after it, which is inorder. Preorder would open with S, and postorder would end with it.

Level Order Must Know

Level order uses a queue. The root goes in, and from then on each key taken out puts its children in.

Level Order in Code

The queue of Chapter 3, holding nodes instead of customers.

public void levelOrderTraverse(BinaryNode<T> root)
{
   QueueInterface<BinaryNode<T>> nodeQueue = new LinkedQueue<>();
   nodeQueue.enqueue(root);
   while (!nodeQueue.isEmpty())
   {
      BinaryNode<T> node = nodeQueue.dequeue();
      System.out.println(node.getData());
      if (node.getLeftChild() != null)
         nodeQueue.enqueue(node.getLeftChild());
      if (node.getRightChild() != null)
         nodeQueue.enqueue(node.getRightChild());
   }
}

Question

Which sequence is the level order of the same tree?

  • A S T U V W X
  • B S T V W U X
  • C V T W S U X
  • D V W T X U S

Level order reads the tree row by row: S, then T and U, then V, W and X. B is the preorder and D is the postorder.

The Stack Behind the Recursion

A recursive traversal keeps its unfinished nodes on a stack. Push a node and go left; when there is no node, pop, visit, and go right.

What the Recursion Costs

Every traversal visits each of the \(n\) nodes once and does a fixed amount of work at each, so all four are \(O(n)\).

The difference is memory. A depth-first traversal holds one path at a time, so it needs \(O(h)\) stack frames; a level-order traversal holds a whole level, so its queue can reach \(O(n)\) entries.

Expression Trees Must Know

Two expression trees. An operator is an internal node, and its operands are its subtrees.

Question

Both trees on the last slide read 2 − 3 × 4 + 5 in infix.

Which reading identifies the tree it came from?

  • A prefix only
  • B postfix only
  • C prefix or postfix
  • D neither one

Both put each operator next to its own operands, so each one names the tree exactly. Only infix needs parentheses, because it writes the operator between its two operands and the grouping is no longer visible.

Rebuilding a Tree

One traversal does not determine a binary tree. A preorder and an inorder of the same tree determine exactly one.

Question

A binary tree has preorder W T Y X Z and inorder T W X Y Z.

Which key is the right child of the root?

  • A T
  • B X
  • C Y
  • D Z

W is the root, so the inorder makes X Y Z its right subtree, and the next preorder key inside that subtree is Y. X is the key that follows W in the inorder, which is not the same thing: X is Y’s left child.

  • Rebuild a tree from its preorder and inorder.

Part 3

Binary Search Trees

trees · traversals · search trees · heaps

The Search Tree Property Must Know

A binary search tree is a binary tree in which, for every node,

  • every key in its left subtree is smaller than the node’s key, and
  • every key in its right subtree is larger.

Each node has a distinct key, and the condition holds at every node, not only at the root. A tree in which each node is merely larger than its own two children is not a search tree.

One comparison at a node settles which subtree the key is in, and the other one is never looked at again.

Question

Which traversal of a binary search tree lists its keys in ascending order?

  • A preorder
  • B postorder
  • C inorder
  • D level order

Inorder takes the left subtree, then the node, then the right subtree — smaller keys, the key, larger keys — and it does that at every node.

Inorder Gives Sorted Order

The tree Part 2 traversed was a search tree, and its inorder came out 5 10 11 12 15 20 30 40.

So a binary search tree can sort: build it with \(n\) adds, then read it off in \(O(n)\).

It also answers what a hash table could not. The smallest key is at the end of the leftmost path, the largest at the end of the rightmost, and every key between two bounds is one partial traversal.

Adding a Key Must Know

An empty binary search tree, and ten keys to add: 37, 2, 45, 48.

Adding a Key

The first 4 keys are in. The rest arrive in this order: 41, 29, 20, 30, 49, 7.

add in Code

private void addEntry(BinaryNode<T> node, T newEntry)
{
   int comparison = newEntry.compareTo(node.getData());
   if (comparison < 0)
   {
      if (node.getLeftChild() == null)
         node.setLeftChild(new BinaryNode<>(newEntry));
      else
         addEntry(node.getLeftChild(), newEntry);
   }
   else
   {
      if (node.getRightChild() == null)
         node.setRightChild(new BinaryNode<>(newEntry));
      else
         addEntry(node.getRightChild(), newEntry);
   }
}

Where a New Key Lands

A new key is always added as a leaf. The walk ends at the first missing child, and that is where the node goes.

Nothing already in the tree moves, which is why add costs one walk down and one assignment — no shifting, as a sorted array needed in Chapter 5.

The ten keys went in with 21 comparisons. In a tree that is one long branch, the same ten would cost \(0 + 1 + \dots + 9 = 45\).

Searching Must Know

The finished tree, and a search for 29. Every comparison throws away one of the two subtrees.

When the Key Is Absent

The finished tree, and a search for 33. Every comparison throws away one of the two subtrees.

Question

How many comparisons does a search for 44 make?

  • A 2
  • B 3
  • C 4
  • D 10

44 is compared with 37, 45 and 41, and 41 has no right child, so the search stops there. 4 counts the missing child as a comparison, and 10 is the whole tree, which is what a search of an unsorted array would cost.

getEntry in Code

private T findEntry(BinaryNode<T> node, T entry)
{
   if (node == null)
      return null;                                 // not in the tree

   int comparison = entry.compareTo(node.getData());
   if (comparison == 0)
      return node.getData();                       // found it
   else if (comparison < 0)
      return findEntry(node.getLeftChild(), entry);
   else
      return findEntry(node.getRightChild(), entry);
}

The comparison at each node has three outcomes. Two of them end the search, and the third throws away one subtree.

Question

add(32) is called on the same tree.

Which node becomes 32’s parent?

  • A 29
  • B 30
  • C 20
  • D 45

The walk is 37, 2, 29, 30, and 30 has no right child. 29 stops one node early, 20 goes left at 29, and 45 goes right at the root even though 32 is smaller than 37.

Removing a Key Must Know

Removing a key is three different jobs, and which one it is depends on how many children the node has.

The Three Removal Cases

children what happens
none The parent’s link to it becomes null.
one That child takes the removed node’s place.
two The inorder successor is copied into the node, and the successor’s own node is removed.

The inorder successor is the next key in sorted order: the smallest key in the right subtree, reached by going right once and then left as far as possible. It has no left child, so removing it is one of the first two cases.

Question

remove(45) is called on the tree from two slides back.

Which key moves into 45’s node?

  • A 41
  • B 49
  • C 48
  • D 37

45 has two children, so the successor moves in: go right to 48, then left as far as possible, which is nowhere. 41 is the inorder predecessor and 49 is the largest key in the right subtree, not the smallest.

What a Search Costs Must Know

Every operation walks one path from the root, so add, remove and a search all cost \(O(h)\).

\(h\) is not fixed by \(n\). For \(n\) keys it is somewhere between \(\lceil \log_2(n+1)\rceil - 1\) and \(n - 1\), depending on the order the keys arrive in.

  • A tree whose levels are full: \(O(\log n)\) per operation.
  • A tree that is one long branch: \(O(n)\), which is Chapter 5’s chain again, with a reference wasted at every node.

The Worst Shape

The same six keys, arriving in sorted order: 2, 7, 20, 29, 30, 37.

Question

Which order builds the shortest search tree from the keys 10 through 70?

  • A 10 20 30 40 50 60 70
  • B 40 20 60 10 30 50 70
  • C 70 60 50 40 30 20 10
  • D 10 70 20 60 30 50 40

B takes the middle key first, then the middle of each half: height 2. The other three hang each key off the end of a branch: height 6.

The Shortest Tree from Sorted Keys

A sorted array of 7 keys. Inserted in this order they would make one long branch, so take the middle key first.

Keeping a Tree Balanced

Rebuilding from a sorted array works once. Keys that arrive one at a time, in whatever order the data comes in, need something else.

A balanced search tree compares the heights of each node’s two subtrees as entries are added, and rearranges a few links when they differ by too much. The keys and the search tree property do not change; only the shape does.

That is the AVL tree, which the next deck builds. It keeps \(h\) at \(O(\log n)\) for every insertion order.

Part 4

Heaps

trees · traversals · search trees · heaps

The Heap Must Know

A max-heap is a complete binary tree in which every node’s key is greater than or equal to the keys of its children.

  • The largest key is therefore at the root, where it can be read in \(O(1)\).
  • A min-heap reverses the comparison, and the smallest key is at the root.
  • The keys are Comparable, as they were in a search tree.

Both rules matter. Complete fixes the shape whatever the keys are; greater than or equal fixes the order along each parent-child link.

A Heap Is Not Sorted

Nothing orders two siblings or two cousins, so the same five keys make several different heaps. A search tree holds the keys in one arrangement; a heap fixes only which key is at the root.

Finding a Key in a Heap

To search a heap for a key that is not the largest, there is no comparison that rules out a subtree, so every node may have to be examined: \(O(n)\).

A search tree finds any key in \(O(h)\) and its largest in \(O(h)\); a heap finds its largest in \(O(1)\) and anything else in \(O(n)\).

Storing a Heap in an Array

A heap is a complete binary tree, and a complete tree has no gaps. That is why it can be stored in an array.

Index Arithmetic Must Know

With the root at index 0, for the node at index \(i\):

\[\text{left child } 2i + 1, \qquad \text{right child } 2i + 2, \qquad \text{parent } \left\lfloor \tfrac{i - 1}{2} \right\rfloor.\]

This works only because the tree is complete: level order fills the array with no holes, so index arithmetic can stand in for every reference.

A binary search tree cannot be stored this way. Its shape depends on the keys, and the gaps would cost more than the references do.

Question

Which parent and child break the max-heap rule?

  • A 0 and 1
  • B 1 and 4
  • C 2 and 5
  • D none of them

Index 5 holds 85 and its parent, index 2, holds 80. Every other parent is at least as large as both of its children. An array that is not sorted can still be a heap.

Adding to a Heap Must Know

An empty max-heap, and the keys arrive in this order: 100, 70, 50, 125.

Adding to a Heap

The heap so far, and three more keys: 45, 60, 10.

Question

add(90): at which index does 90 come to rest?

  • A 7
  • B 3
  • C 1
  • D 0

90 goes into index 7, whose parent is index 3 holding 70, so the two swap. The next parent is index 1, holding 100, and 90 is smaller, so it stops. 7 is where it landed before bubbling.

add in Code

public void add(T newEntry)
{
   heap[lastIndex] = newEntry;
   int index = lastIndex;
   lastIndex++;
   while (index > 0)
   {
      int parent = (index - 1) / 2;
      if (heap[index].compareTo(heap[parent]) <= 0)
         return;                                   // the heap is in order
      T temp = heap[index];
      heap[index] = heap[parent];
      heap[parent] = temp;
      index = parent;
   }
}

Removing the Maximum Must Know

The largest key is at the root, so finding it is easy. The tree still has to be complete after it leaves.

Why the Last Entry Moves Up

removeMax always takes the root, and the last entry is the only one that can leave without putting a hole in the tree.

So removeMax does both: it reports the root, moves the last entry into it, and then moves that entry down until the heap property holds again.

The entry always swaps with the larger child. Swapping with the smaller one would leave the larger child under a key smaller than itself, and the heap would still be broken.

removeMax in Code

public T removeMax()
{
   T root = heap[0];
   lastIndex--;
   heap[0] = heap[lastIndex];      // the last entry moves to the root
   reheap(0);                      // and sinks from there
   return root;
}

The method itself is four assignments. reheap does the rearranging.

reheap in Code

private void reheap(int index)
{
   int left = 2 * index + 1;
   while (left < lastIndex)
   {
      int larger = left;
      int right = left + 1;
      if (right < lastIndex && heap[right].compareTo(heap[larger]) > 0)
         larger = right;                 // the larger of the two children
      if (heap[index].compareTo(heap[larger]) >= 0)
         return;                         // in order: nothing left to do
      swap(index, larger);
      index = larger;
      left = 2 * index + 1;
   }
}

What a Heap Costs Must Know

A complete tree of \(n\) nodes has height \(\lfloor \log_2 n \rfloor\), and both operations follow one path of it.

  • getMax reads index 0: \(O(1)\).
  • add bubbles up at most \(h\) times: \(O(\log n)\).
  • removeMax moves one entry down at most \(h\) times: \(O(\log n)\).
  • Finding any other key: \(O(n)\).

No insertion order can push the height toward \(n\) the way it can in a search tree, because complete is part of the definition of a heap.

Question

Which operation is \(O(1)\) in a max-heap but not in a binary search tree?

  • A finding the largest key
  • B finding a given key
  • C listing the keys in ascending order
  • D adding a key

The largest key is the root of a heap and the end of a search tree’s rightmost path. B is \(O(n)\) in a heap and C is \(O(n \log n)\).

The Priority Queue, Implemented

Chapter 3 gave the priority queue its interface: add puts an entry in, and remove takes out the one with the highest priority, not the one that arrived first.

A sorted chain gives \(O(1)\) removal and \(O(n)\) insertion. An unsorted array gives the reverse. A heap makes both \(O(\log n)\), and Java’s PriorityQueue is a heap.

Removing every entry in turn sorts them: \(n\) removals at \(O(\log n)\) each is \(O(n \log n)\), which is heapsort.

Costs of the Four Structures Must Know

Worst case for the array and the hash table, average for the search tree.

structure search add largest key keys in order
sorted array \(O(\log n)\) \(O(n)\) \(O(1)\) \(O(n)\)
hash table \(O(1)\) \(O(1)\) \(O(n)\) \(O(n \log n)\)
binary search tree \(O(\log n)\) \(O(\log n)\) \(O(\log n)\) \(O(n)\)
max-heap \(O(n)\) \(O(\log n)\) \(O(1)\) \(O(n \log n)\)

The search tree row is an average, and it holds only while the tree stays short. The AVL tree of the next deck keeps it short.
